# ofLSA — глобальный анализ устойчивости 3D-течений в OpenFOAM

*English version: [README.md](README.md)*

Этот репозиторий отвечает на один вопрос о течении: **при каком числе Рейнольдса стационарное
течение перестаёт быть стационарным, и как выглядит возмущение, которое при этом растёт?**

Здесь два солвера для OpenFOAM-14 (openfoam.org), написанные в группе Ю. Фельдмана
(Университет Бен-Гуриона), и готовый пример — 3D-каверна с движущейся крышкой.

---

## 1. Идея за пять минут

Возьмём куб с жидкостью, у которого верхняя крышка едет с постоянной скоростью. При малых Re
жидкость устанавливается в стационарный вихрь. Если поднимать Re, в какой-то момент
стационарный вихрь «не удерживается»: любое крошечное возмущение начинает расти, и течение
начинает колебаться. Это и есть **критическое число Рейнольдса**. Для куба оно около 1929.

Находим его в два шага, на каждый свой солвер.

**Шаг 1 — стационарное течение (`NewtonSolver`).**
Нужно стационарное течение даже там, где оно неустойчиво (в эксперименте его не увидишь, но
как решение уравнений оно существует). Обычный солвер с шагами по времени его не найдёт — он
«уплывёт» в колебания. Поэтому стационарные уравнения Навье–Стокса решаются напрямую методом
Ньютона: приближение → поправка → снова, пока невязка не станет крошечной.

**Шаг 2 — растёт ли малое возмущение (`StabilitySolver`).**
К стационарному течению добавляем крошечное возмущение и смотрим, как оно развивается. Раз оно
маленькое, его уравнения линейные, а решения ведут себя как `e^(λt)` с комплексным
`λ = λr + i·ω`:

| | что значит |
|---|---|
| `λr < 0` | возмущение затухает — течение **устойчиво** |
| `λr > 0` | растёт — **неустойчиво** |
| `λr = 0` | граница: это Re и есть **критическое** |
| `ω` | угловая частота колебаний, которые появятся |

Солвер находит несколько `λ` с наибольшей `λr` (самые «опасные» возмущения) и записывает их
форму — **собственную моду** — её можно посмотреть в ParaView.

**В чём сложность и что тут особенного.** На сетке 256³ около 17 млн ячеек, это ~70 млн
неизвестных. Собрать и обратить такую матрицу невозможно. Здесь матрица вообще не собирается:
все операции делаются «на лету» штатными операторами OpenFOAM, а большие линейные системы
решаются итерационно (FGMRES) с хорошим предобуславливателем (модифицированный дополненный
лагранжиан, mAL). Собственные числа ищет PARPACK (метод Арнольди) в режиме *shift-invert*:
ты говоришь, где примерно искать (`σ`), и он быстро находит ближайшие к этой точке числа.

## 2. Что нужно

- **Linux** (рабочая станция или кластер, root не нужен).
- **OpenFOAM-14** с openfoam.org. *Не* ESI-версия (openfoam.com, v2406/v2606) — это другой код.
- **MPI** (OpenMPI) с компилятором Фортрана — обычно приходит вместе с OpenFOAM; на кластере
  `module load gcc openmpi`.
- **ARPACK/PARPACK** — если нет, скрипт сборки сам поставит его в домашнюю папку.

Установка OpenFOAM-14 на Ubuntu (нужен root):
```bash
sudo sh -c "wget -O - https://dl.openfoam.org/gpg.key > /etc/apt/trusted.gpg.d/openfoam.asc"
sudo add-apt-repository http://dl.openfoam.org/ubuntu
sudo apt update
sudo apt install openfoam14 libarpack2-dev libparpack2-dev
```
На кластере без root: модуль OpenFOAM-14 кластера или контейнер (раздел 8).

## 3. Первый запуск по шагам

```bash
git clone https://github.com/<owner>/<repo>.git ofLSA
cd ofLSA
```

**Подключить окружение.**
```bash
scripts/oflsa-shell
```
Откроется новая оболочка с OpenFOAM-14 и этим проектом, приглашение станет `(ofLSA) ...$`.
Следующие команды вводи *после* того, как оно появится.
(Вместо этого можно `source /opt/openfoam14/etc/bashrc`, потом `source etc/bashrc`.)

**Собрать.**
```bash
./Allwmake
```
Компилирует библиотеку FGMRES и оба солвера (пара минут). Если PARPACK не найден, сначала
собирается он (5–20 минут). В конце должно быть:
```
Built:
.../bin/NewtonSolver
.../bin/StabilitySolver
```

**Запустить пример.**
```bash
cd tutorials/lidDrivenCavity3D
nohup ./Allrun -np 4 > log.Allrun 2>&1 &
tail -f log.Allrun
```
- `-np 4` — сколько ядер использовать. Ставь столько, сколько есть.
- `nohup ... &` — расчёт в фоне, не умрёт, если закрыть терминал.
- `tail -f` — показывает ход расчёта; `Ctrl+C` выходит из просмотра, расчёт идёт дальше.

Что делает `Allrun` по порядку:

1. `blockMesh` — строит сетку (50×50×50, сгущённую к стенкам);
2. `decomposePar` — режет её на куски, по одному на ядро;
3. `NewtonSolver` — стационарное течение, поднимая Re постепенно (200 → 500 → 1000 → … → цель),
   потому что из покоя при большом Re Ньютон не сходится;
4. `StabilitySolver` — собственные числа и мода при целевом Re;
5. `reconstructPar` — склеивает куски обратно.

Newton — минуты, устойчивость — дольше, зависит от числа ядер.

## 4. Как читать результат

**В `log.Allrun`** — по строчке на каждый шаг Newton:
```
NewtonSolver at Re = 1000 ...
Newton 6: momentum=3.1e-08 continuity=2.2e-12
```
Маленькие числа — сошёлся.

**Ответ** — в конце `log.Allrun` (или `log.StabilitySolver`):
```
growth rate Re(lambda)      = -0.0123      <- λr: отрицательное = устойчиво
angular frequency Im(lambda)= 0.581        <- ω
```

**Мода в ParaView:**
```bash
paraview case.foam
```
*Apply*, выбрать поле `leadingEigenModeRealU` (и `leadingEigenModeImagU`). Это
действительная и мнимая части растущего возмущения; изоповерхность одной компоненты
скорости показывает его 3D-структуру.

## 5. Что лежит в папке кейса

```
tutorials/lidDrivenCavity3D/
├── 0/U, 0/p                  начальные и граничные условия (скорость крышки = 1)
├── system/
│   ├── blockMeshDict         сетка
│   ├── newtonProperties      настройки стационарного солвера  (Re, допуски)
│   ├── stabilityProperties   настройки солвера устойчивости   (Re, сдвиг σ, число мод)
│   ├── decomposeParDict      разбиение по ядрам (выставляет Allrun)
│   ├── controlDict, fvSchemes, fvSolution    стандартные файлы OpenFOAM
├── Allrun                    запускает всё
└── Allclean                  удаляет результаты, настройки остаются
```

Re считается по скорости крышки (1) и стороне куба (1): ν = 1/Re.

## 6. Рецепты: как поменять кейс

Работай с копией, оригинал оставь как образец:
```bash
cp -r tutorials/lidDrivenCavity3D ~/myCavity && cd ~/myCavity
```
Вспомогательные скрипты (`setRe`, `makeCavityMesh.py`) после подключения окружения доступны
из любой папки.

**Поменять число Рейнольдса**
```bash
setRe 1900
./Allrun -np 8
```
`setRe` меняет Re сразу в *обоих* файлах — `newtonProperties` и `stabilityProperties`. Они всегда
должны совпадать: устойчивость считается для течения именно при этом Re.

**Поменять сетку**
```bash
makeCavityMesh.py 100 0.0975          # внутри папки кейса
```
`100` — ячеек по каждому направлению; `0.0975` — насколько сильно ячейки сгущаются к стенкам
(0 = равномерная). Перезаписывает `system/blockMeshDict`, потом снова `./Allrun`.
Размеры: 50³ — любой комп; 100³ (1 млн ячеек) — мощная рабочая станция; 256³ (17 млн) —
кластер (в статье 256 ядер и 14–30 часов).

**Больше или меньше ядер** — просто `./Allrun -np 16`.

**Искать другие собственные числа** — в `system/stabilityProperties`:
- `sigmaImag 0.5` — где искать по оси частот; ставь около ожидаемой `ω`;
- `arnoldiNev 2` — сколько чисел найти; `arnoldiNcv` — рабочий базис, держи его не меньше
  `2·nev + 1`.

Если менял только это, стационарное течение пересчитывать не нужно:
```bash
mpirun -np 8 StabilitySolver -parallel > log.StabilitySolver 2>&1
```

**Newton не сходится при твоём Re** — делай шаги мельче:
```bash
./Allrun -np 8 -ramp "250 500 750 1000 1250 1500 1750"
```

**Найти критическое Re** — посчитай при нескольких Re вокруг ожидаемого (например, 1850, 1900,
1950, 2000), запиши `λr` для каждого и интерполируй, где `λr = 0`.

## 7. Если что-то пошло не так

| Что видишь | Почему | Что делать |
|---|---|---|
| `source .../bashrc` виснет или `_foamSource: command not found` | OpenFOAM при загрузке вызывает `paraview --version`, на некоторых Ubuntu это виснет | `scripts/oflsa-shell`; или один раз `Ctrl+C` |
| `exe-not-found` от `mpirun` | в этом терминале не подключён OpenFOAM | сначала `scripts/oflsa-shell` |
| `Newton FGMRES failed after 200 iterations` | Ньютон стартовал слишком далеко от решения | мельче шаги `-ramp` |
| `PARPACK Arnoldi basis vector ... left the required ... solenoidal space` | накопились мелкие ошибки внутренних решений | в `stabilityProperties`: `shiftInvertTolerance 1e-6` и/или `arnoldiConstraintTolerance 1e-3` |
| `cannot find -liomp5 / -lifport` | старый `Make/options` под компилятор Intel | брать файлы из этого репозитория |
| `PARPACK not found` | не установлен ARPACK | `scripts/install_arpack.sh` или `sudo apt install libarpack2-dev libparpack2-dev` |
| ParaView не открывается из терминала | та же проблема с ParaView | `nohup paraview case.foam > /dev/null 2>&1 < /dev/null &` |

## 8. Кластер без OpenFOAM: контейнер

В контейнере уже есть OpenFOAM-14, PARPACK и солверы. Нужен Apptainer (Singularity), он есть
почти на всех кластерах:
```bash
apptainer pull oflsa.sif docker://ghcr.io/<owner>/<repo>:latest
cd ~/myCavity
apptainer exec ~/oflsa.sif oflsa-run blockMesh
apptainer exec ~/oflsa.sif oflsa-run decomposePar
mpirun -np 32 apptainer exec ~/oflsa.sif oflsa-run NewtonSolver -parallel
mpirun -np 32 apptainer exec ~/oflsa.sif oflsa-run StabilitySolver -parallel
```
Для расчёта на нескольких узлах OpenMPI кластера должен быть совместим с тем, что в
контейнере — спроси поддержку кластера, какой модуль грузить.
